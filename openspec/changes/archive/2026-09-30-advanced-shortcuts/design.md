# Design

## Context

See `proposal.md` — Why. What shapes the approach:

- **Today's shape.** `src/ui/quickReplies.ts` holds `DEFAULT_QUICK_REPLIES: readonly QuickReply[]` with
  `{ id, label, text, submit }` and two helpers, `replyMessage` (`{ type: "submit" | "input", data }`) and `replyHint`
  (the tooltip). `TerminalView` (`src/ui/sessionPanel.tsx`) maps over the constant. Nothing server-side knows the list:
  the browser sends a `submit` message over the terminal WebSocket and `src/server/sessions/submit.ts` types the text,
  watches for its echo and only then presses Enter.
- **Configuration.** `~/.openspec-dashboard/config.json` is validated by one zod schema in `src/server/config.ts`;
  `agentSessions` already carries `enabled`, `agents`, `defaultAgent` and `consoleDir`. Defaults live in
  `src/shared/agentDefaults.ts` (`defaultAgentSessions()`), shared by server and UI. Every field's default is applied on
  load, which is how a configuration predating a field keeps working (the pattern `consoleDir` and `prompts` use).
- **Settings.** `src/ui/agentSettings.tsx` renders the `agents` section from a draft `Config` and an `update(patch)`
  callback; `src/ui/settings.tsx` owns the draft, the save bar and the PUT. The section list in
  `src/ui/settingsSections.ts` is a deep-link contract, so nothing here may add a section.
- **The UI already has the config.** `useSessionUi()` exposes `config: Config | null` (used for
  `config?.agentSessions.enabled`), so `TerminalView` can read the shortcuts without a new fetch or prop.
- **Invariants.** A shortcut's prompt is typed into a running agent, so it must stay a single line with no control
  characters (invariant: the dashboard never presses Enter itself — `submit.ts` decides, and a `\n` inside the text would
  submit behind that decision's back). Nothing here touches a repository, the network or git.

## Goals / Non-Goals

**Goals:**

- One representation of a shortcut, in `src/shared/`, used by the config schema, the settings editor and the terminal row.
- A configuration that predates shortcuts loads with the shipped four, wording and order byte-identical to today's.
- The console's send path is untouched: same message, same echo rule, same unsent notice.

**Non-Goals:**

- Per-agent or per-repository shortcut sets (see D2).
- Placeholders, templating or any substitution into a prompt (see D3).
- Keyboard accelerators for shortcuts, grouping, icons, or a shortcut that runs a dashboard action rather than sending
  text.
- Any server-side knowledge of the list beyond validating it (see D6).

## Decisions

### D1 — `Shortcut` is a shared type; `{ id, title, prompt }`

`src/shared/types.ts` gains:

```ts
export interface Shortcut {
  id: string;
  /** What the control reads. Never sent. */
  title: string;
  /** Typed into the agent's terminal exactly as written; one line, no placeholder. */
  prompt: string;
}
```

and `AgentSessionsConfig.shortcuts: Shortcut[]`. `id` keeps the list keyed in Preact across edits and reorders, and is
what a validation message can name; it is generated by the UI with the existing `slugId` helper (as `addAgent` does),
never typed by the user.

*Alternatives:* keeping `label`/`text` (the prompt's own words are `title` and `prompt`, and the rename is the
readable signal that the two are now independent); a plain `[title, prompt]` tuple (no stable key for the editor);
`Record<id, …>` (loses the order, which is the row's order).

### D2 — One global list under `agentSessions.shortcuts`, not per agent profile

A shortcut is an answer to a question an agent asked ("yes, go ahead"), not a capability of a particular CLI. The row is
rendered by `TerminalView`, which is given a session id and deliberately knows nothing about repositories, changes or
profiles — the main console and Integrate use the same component. A per-profile list would mean threading the profile
into that component and deciding what an Integrate session, which belongs to no repository, should show.

*Alternative:* `AgentProfile.shortcuts`, per agent. Rejected as scope the prompt did not ask for and a lookup
`TerminalView` cannot do today; if it is ever wanted, a per-profile list can override this global one without changing
the shortcut type or the send path.

### D3 — The prompt is sent verbatim: no placeholder, ever

`{change}` is meaningful in a starter prompt because the dashboard starts that session for a known change. A shortcut is
typed into whatever session is open, including the main console and Integrate, which have no change. Rather than define
a placeholder that is empty in two of three cases, the schema rejects nothing and substitutes nothing: what the field
says is what is typed. This also keeps the spec's "MUST NOT add to or alter" literally checkable and keeps `submit.ts`'s
echo comparison comparing the exact configured text.

### D4 — Validation belongs in the config schema, next to the other prompts

`src/server/config.ts` gets:

```ts
const shortcutSchema = z.object({
  id: z.string().regex(/^[a-z0-9][a-z0-9-]{0,31}$/),
  title: z.string().trim().min(1).max(40),
  prompt: z.string().trim().min(1).max(2000)
    .refine((v) => !/[\u0000-\u001f\u007f]/.test(v), { message: "must be a single line without control characters" })
    .refine(noBypass, { message: BYPASS_MESSAGE }),
});
```

added to `agentSessionsSchema` as `shortcuts: z.array(shortcutSchema).default(() => defaultAgentSessions().shortcuts)`,
with unique ids checked in the existing `superRefine` beside the agent-id check. `40` keeps a title on a button; `2000`
is room for a paragraph while bounding what gets typed into a terminal. `.trim()` normalises on the way in, so a title
of spaces fails `min(1)` — the same shape the agent `name` and `prompts` fields already use. The bypass check is applied
for the same reason it is applied to every other prompt: the dashboard does not help switch off an agent's permission
checks.

*Alternative:* validating only in the browser. Rejected — the schema is the one gate the PUT and a hand-edited file both
pass through.

### D5 — Migration by default value, not by a migration step

`shortcuts` absent ⇒ zod's `.default()` supplies `structuredClone(DEFAULT_SHORTCUTS)`. No version bump, no rewrite of
the file on load, and a configuration with `shortcuts: []` stays empty because the key is present. There is deliberately
**no** `FORMER_PROMPTS`-style upgrade of an edited list: `FORMER_PROMPTS` exists for a preconfigured prompt whose
improvement the user should inherit, while a shortcut list is small, whole and entirely the user's — silently appending
a new default to it would be a write the user did not ask for. "Restore defaults" in Settings is the explicit way back.

### D6 — The row reads the loaded config; the server stays out of it

`TerminalView` calls `useSessionUi()` and renders what `visibleShortcuts(config, running, connected)` returns, hiding
the row (label included) when that is empty. The decision is that helper rather than a condition in the JSX because the
project has no DOM-rendering tests: as with `rowScrollLeft` and `navOffset`, the rule is a pure function with unit tests
and the rendering itself is checked in a browser. `quickReplies.ts` keeps its two helpers, retyped onto `Shortcut`:
`shortcutMessage(s) → { type: "submit", data: s.prompt }` and `shortcutHint(s) → 'sends "<prompt>"'`. `QuickReply.submit`
and the `input` branch go: no shortcut was ever offered as typed-only, and the safe path already covers the menu case
that a typed-only variant was there to hedge. The server needs no change — the terminal socket accepts arbitrary input
from the browser by design (it is a terminal), so a configured prompt is not new wire surface; `webSocketRefusal` remains
the guard that matters.

### D7 — Editor: a list inside the existing Agent sessions section

A `Shortcuts` block in `agentSettings.tsx`, between `Agents` and `Console`, inside the same
`<fieldset disabled={!settings.enabled}>`: per row a title `input`, a prompt `input` (single-line, matching the
single-line rule), `↑`/`↓`, `Remove`, and below the list `+ Add shortcut` and `Restore defaults`. It edits the draft
through the existing `set({ shortcuts })`, so the save bar, the "unsaved changes" indicator and the refused-save
behaviour all come for free and no section id is added. Reordering is two buttons over an array move rather than
drag-and-drop: no new dependency and it works from the keyboard.

### D8 — Order-and-move as a tested pure helper

The array move (`moveShortcut(list, index, delta)`, unchanged at the ends) goes next to the other shortcut helpers so it
is unit-testable without a DOM, the pattern the project uses for `rowScrollLeft` and `navOffset`.

## Risks / Trade-offs

- **A user empties the list and loses the buttons** → Valid and specified (a terminal without the row is what the
  console was before it existed); `Restore defaults` brings the four back in one click.
- **A long prompt makes the echo check slower or more fragile** → `submit.ts` already disregards escape sequences and
  wrapping and accepts a leading portion for long text; the 2000-character bound keeps it in the range that path was
  built for, and a prompt that never echoes ends in the existing "typed but not sent" notice rather than a stray Enter.
- **A long title stretches the shortcut row** → 40 characters and the row's existing wrapping; nothing else in the panel
  moves.
- **Terminology drift: "default responses" in older spec text, code comments and tests** → the delta renames the
  requirement; the tasks rename the module's wording in the same commit as its type change, so `Shortcuts:` (already the
  visible label) becomes the one word used.
- **Two in-flight changes also edit `agentDefaults.ts` and `agentSettings.tsx`** → this change only adds a constant and a
  block; conflicts, if any, are additive.

## Migration Plan

Forward: ship. A configuration without `shortcuts` gains the defaults on load (D5) and is written with them the next
time Settings is saved. Backward: an older binary reading a configuration that carries `shortcuts` drops the unknown key
(zod strips it) and shows its built-in four, so a downgrade loses the customisation but nothing breaks.
